Tally detection (Phase 7, `src/main/tally/detect.ts`, no Electron import): `createTallyDetector({getTarget,getCompanyGuid,setCompanyGuid,post?,timeoutMs?,onChange?})` -> `{detect,last,selectCompany,start,stop,status}`. `detect()` never throws and concurrent calls share one probe. Probe 1 (`ID LBCompanyNames`, Company collection, NATIVEMETHOD Name/GUID/StartingFrom/EndingAt: only loaded companies appear) gives reachability and the company list; probe 2 (Function `$$ProdInfo`, answer in `<RESPONSE>`) gives the version and is best effort. Both request ids are `assumed` (TW-PING, TW-PRODINFO). Result `TallyDetection {state: ok|choose_company|no_company|unreachable|rejected|not_tally, ok, code (LB_TALLY_UNREACHABLE | LB_TALLY_REJECTED | TALLY_COMPANY_NOT_LOADED | null), host, port, version, companies[{name,guid,startingFrom,endingAt}], selected, message, checkedAt}`; `message` is plain language with the fix (enable XML server: F1, Settings, Connectivity, Client/Server configuration). Company selection: the saved `config.companyGuid` (the GUID, or the name when Tally gave none) must match a loaded company; a single loaded company is auto-selected and saved; several with none saved gives `choose_company`. Responses are decoded as UTF-8 or UTF-16 (BOM) and illegal XML 1.0 characters are stripped and counted in the log. Re-probes every 60 s and on demand; `Status.tally` = `{ok, version, company}` from the last probe. `LbErrorCode` gained `LB_TALLY_UNREACHABLE`, `LB_TALLY_REJECTED`. Phase 8 (`client.ts`) may inject its serialised transport as `deps.post`.

Tally client (Phase 8, `src/main/tally/client.ts` + `xml.ts`, no Electron import): `createTallyClient({getTarget,getCompanyName?,post?,timeoutMs?,retries?,backoffMs?,sleep?,maxResponseBytes?})`. One serialised queue (a single request in flight; priority `entry` before `sync`, FIFO within; a failed job never blocks the next). Defaults: timeout 60 s, 2 retries, backoff 500 ms doubling. Retry rule: exports retry on any connection error or timeout; imports retry ONLY when the connection was refused (nothing reached Tally), never after a reset, timeout or answer. Response cap 512 MB. Errors are `TallyError extends LbError {code: LB_TALLY_UNREACHABLE | LB_TALLY_REJECTED, detail: TALLY_UNREACHABLE | TALLY_TIMEOUT | TALLY_COMPANY_NOT_LOADED | TALLY_REJECTED | TALLY_MALFORMED | TALLY_RESPONSE_TOO_LARGE, retryable, requestId}`: `LINEERROR` matching SVCurrentCompany/company-not-open wording gives COMPANY_NOT_LOADED (retryable, assumed wording TW-ERRTEXT), any other LINEERROR or `Unknown Request` gives REJECTED, unparseable XML after stripping illegal characters gives MALFORMED (retryable; the caller skips that table and continues, TALLY_WIRE section 9). `importData` returns `ImportResult {ok, ambiguous, created, altered, ignored, combined, errors, lastVchId, lastMId, lineErrors[], statusDesc}`: ok = no LINEERROR, ERRORS 0, CREATED+ALTERED > 0; ambiguous = nothing created or IGNORED/COMBINED > 0 or an unreadable answer (never retried blindly); STATUS 0 fills `statusDesc`. Row shape from `xml.ts` `nodeToRow`: attributes as `@NAME`, simple tags as text (repeated tags as `string[]`), tags with children as `Row[]` under the tag name (always an array). `collectionStream` parses one object at a time from the decoded text (no whole-document tree). Builders in `xml.ts`: `buildCollectionRequest`, `buildFunctionRequest`, `buildEnvelope`, `escapeXml`, `decodeResponse` (UTF-8, UTF-16 LE/BE with BOM, illegal XML 1.0 characters and numeric references stripped and counted in the log); names, fields and dates are validated against injection. `getCompanyName` supplies SVCURRENTCOMPANY (index.ts passes the detector's selected company). The detector now uses `client.queuedPost`, so detection and every later request share one queue.

Company info (Phase 9, `src/main/tally/company.ts`, no Electron import): `createCompanyInfo({client,getCompanyName,getCompanyGuid?,cacheFile?,onChange?})` -> `{read(),last()}`. `read()` sends collection `LBCompany` (type Company; NATIVEMETHOD for every simple `tm_company` tag, FETCH `ADDRESS.LIST`; SVCURRENTCOMPANY = selected company), picks the object whose `NAME` equals the selected company (and whose GUID equals `config.companyGuid` when both are known), and maps it to `CompanyRecord` = the `tm_company` columns in data_model order (dates `YYYYMMDD` to ISO, ints with defaults, `address` = ADDRESS lines or null, `alter_id` = max(alter_id_master, alter_id_voucher)). `tally_serial`: the `FNRESULT` element of the row if Tally sent one, otherwise a separate Function export `$$LicenseInfo:SerialNumber` (best effort: failure leaves `''`, never an error); both shapes are `assumed` (TW-LICENSEINFO). Errors: no selection -> `Error('No company selected')`; company not in the answer -> `TallyError TALLY_COMPANY_NOT_LOADED` (retryable). The record is cached to `userData/company.json` (atomic write, informational only) and `onChange` fires only when it changed. `checkBinding(bound, current)` -> `unbound|match|mismatch|unknown` is a pure helper: no enforcement, no stored binding yet (Open question). `index.ts` reads the record whenever detection reports `ok`. The mock Tally answers `$$LicenseInfo:SerialNumber` (`LB_MOCK_TALLY_SERIAL` overrides).

Masters pull (Phase 10, `src/main/tally/masters/`, no Electron import): `createMasters({client,getCompanyName,getCompanyGuid,getAsOf?,onPulled?})` -> `{pull(),last()}`. `pull()` sends one collection request per master kind, one at a time through the client (priority `sync`, SVCURRENTCOMPANY = selected company): `LBGroups, LBLedgers, LBVoucherTypes, LBStockGroups, LBStockCategories, LBUnits, LBGodowns, LBStockItems, LBCostCentres, LBCurrencies, LBEmployees, LBTaxUnits` (request ids, types and object names come from `data_model.json` `tables.<t>.tally`). NATIVEMETHOD = every simple tag of the table and its follows_parent tables; FETCH = nested lists and list-valued columns (`ADDRESS.LIST`, `LEDMAILINGDETAILS.LIST`, `LEDGSTREGDETAILS.LIST`, `BILLALLOCATIONS.LIST`, `GSTDETAILS.LIST`, `BATCHALLOCATIONS.LIST`, `LANGUAGENAME.LIST`, `HSNDETAILS.LIST`, ...). Result `MastersResult = {companyGuid, asOf, tables, counts}` where `tables` has the 18 `tm_*` master tables (all except `tm_company`, which is Phase 9) as rows in data_model column order, decimals as canonical strings, dates ISO. Errors: no selection -> `Error('No company selected')`; company record not read yet -> `Error('Company record not read yet')`; any Tally error aborts the whole pull (no partial result, `last()` unchanged). `mapMasters({rows,companyGuid,asOf})` is the pure mapper (also exported). Derivations per TALLY_WIRE section 7: `company_guid`, `name_lc`, `n:<name>` GUID fallback, `*_guid` by case-insensitive exact name match within the table (empty when not found, never fuzzy), group `reserved_root` and `nature` by walking the parent chain (cycle-safe), ledger `group_guid` and `reserved_root`, voucher type `base_kind` by walking parents to a reserved name in `ref_voucher_kind.tally_name` (else `unknown`), ledger primary contact row from the ledger's own contact columns, stock item aliases (names after the first of `LANGUAGENAME.LIST`), `closing_rate` = closing_value / closing_qty (2 decimals, half away from zero), GST head rates from `GSTRATEDUTYHEAD` (`Central Tax, State Tax, Integrated Tax, Cess`). `closing_as_of` = `asOf` (default: today, local). The column map is generated: `node tools/gen-master-columns.mjs` writes `masters/columns.ts` from `data_model.json`. Storing the rows is Phase 15/16; the scheduler (Phase 18) calls `pull()` when `alter_id_master` changed. All Tally tags and request ids are `assumed` (TW-FETCH and the other TW items) exactly as in TALLY_WIRE.

Vouchers pull (Phase 11, `src/main/tally/vouchers/`, no Electron import): `createVouchers({client,getCompanyName,getCompanyGuid,getCompanyState,getMasters,onPulled?})` -> `{pull(opts),last()}`; `opts = {from,to,sinceAlterId?,lookbackDays?,today?}` (ISO dates, inclusive). `pull()` sends collection `LBVouchers` (type Voucher; NATIVEMETHOD = simple `tx_voucher` tags plus `MASTERID`; FETCH = the ledger, inventory, accounting/batch/bill allocation and description lists; SVFROMDATE/SVTODATE = the window; priority `sync`). Without `sinceAlterId` it is a full window pull (`mode:'full'`). With it, the filter formula `LBChanged` = `$AlterID > <cursor>` is added (`mode:'incremental'`) and, when `lookbackDays > 0`, a second unfiltered read of the last N days (clamped into the window) is merged by GUID so edits that kept an old AlterID are still caught (TALLY_WIRE section 4). The window is enforced again on the answer's `DATE`. Result `VouchersResult = {mode,tables,maxAlterId,guids,counts}`: `tables` = `tx_voucher, tx_ledger_line, tx_inventory_line, tx_batch_alloc, tx_bill_alloc, tx_tax_line` in data_model column order. `maxAlterId` = max(cursor, highest alter_id in the pull); the CALLER stores it after a successful vault commit (the vault is Phase 15/16, the scheduler Phase 18). Errors: invalid window, no selection, `Company record not read yet`, `Masters not pulled yet` (names are resolved against the Phase 10 masters); a Tally error aborts the pull and leaves `last()` unchanged. `mapVouchers({rows,companyGuid,companyState,masters})` is the pure mapper. Rules: kind = resolved voucher type `base_kind` (`unknown` if unresolved), `party_guid`/`ledger_guid`/`stock_item_guid`/`godown_guid` by case-insensitive exact name (empty when not found), `counts_in_books = not (cancelled or optional or void)` copied with `voucher_date`/`voucher_kind` onto every child row; line keys: ledger lines in source order (`ALLLEDGERENTRIES` then `LEDGERENTRIES`), then inventory accounting allocations (`source='inv_alloc'`, `inv_line_index`); inventory lines `ALL`, plain, `OUT`, then `IN` (`tx_batch_alloc.is_destination` for `IN`); `alloc_index` per owner; headline `amount` per CALC_SPECS section 3 with exact decimal arithmetic (cancelled = 0); `tx_tax_line` per inventory line of a non-cancelled invoice from the item's GST slab in force on the voucher date, heads cgst+sgst when place of supply equals the company state else igst, plus cess when non-zero, `tax_amount` = taxable x rate / 100 to 4 decimals half away from zero. The column map is generated into `vouchers/columns.ts` by `node tools/gen-master-columns.mjs`. Deletion detection is Phase 12.

Deletes and renames (Phase 12, `src/main/tally/reconcile.ts`, no Electron import): `createReconciler({client,getCompanyName,getCompanyGuid})` -> `{checkDeleted({from,to,stored,allowEmpty?})}`; `stored` = `[{guid,date}]` of the vouchers in the vault. It sends collection `LBVoucherGuids` (type Voucher, NATIVEMETHOD `GUID`, `ALTERID`, SVFROMDATE/SVTODATE; request id `assumed`, the mock serves it from `voucher_guid_list.xml`) and returns `{deleted, tallyCount, comparedCount, ops}`: `deleted` = stored vouchers dated inside the window whose guid Tally did not list (a voucher dated outside the window is not compared; cancelled and optional vouchers are listed by Tally so they stay). `ops` = `ChangeOp[]` `[{tx_voucher, delete_children, [{company_guid,guid}]}, {tx_voucher, delete, [{company_guid,guid}]}]` (SYNC_SPEC section 4 order), empty when nothing was deleted; the chunker (Phase 20) chunks them and the vault (Phase 16) applies the same with `removeVouchers(tables, guids)`. Safety: an empty Tally answer while vouchers are stored throws `Error` with `code='RECONCILE_EMPTY_ANSWER'` (unless `allowEmpty`), and any Tally error throws, so a failed read never deletes. Run it after the voucher sync of the same window (an edited voucher whose date moved must be pulled first). `deletedCheckDue({lastCheckedAt,now,manual?,intervalH?})` -> boolean (default 24 h, constants `desktop.deleted_check_interval_h`; manual always true). Renames: `detectRenames(oldMasters,newMasters)` -> `Rename[] {table,guid,oldName,newName}` for masters with an unchanged real guid and a changed name (rows with an `n:<name>` fallback guid are skipped: their identity changes). `applyRenames(storedVoucherTables, renames)` -> `{tables, affectedVouchers, ops}`: corrects the denormalised names by guid only (`tx_voucher.party_name` and `voucher_type_name`, `tx_ledger_line.ledger_name`, `tx_bill_alloc.ledger_name`, `tx_inventory_line.stock_item_name` and `godown_name`, `tx_batch_alloc.godown_name`), returns one `upsert` per changed table in sync order (rows replace by primary key, no `delete_children` needed), is pure and idempotent. The renamed master itself is re-sent by the normal master refresh (as in `sync_examples/delta_sequence.jsonl`). Nothing calls these until Phase 18.

Closing balances (Phase 13, `src/main/tally/closing.ts`, no Electron import): `createClosing({client,getCompanyName,getAsOf?,onRead?})` -> `{read(),last()}`. `read()` sends three small collections one at a time (priority `sync`, SVCURRENTCOMPANY = selected company): `LBClosingGroups` (type Group; `GUID, CLOSINGBALANCE, OPENINGBALANCE`), `LBClosingLedgers` (type Ledger; `GUID, CLOSINGBALANCE`, FETCH `BILLALLOCATIONS.LIST`), `LBClosingStock` (type StockItem; `GUID, CLOSINGBALANCE, CLOSINGVALUE`). Request ids are `assumed` (TALLY_WIRE section 6 names no request); the mock serves them from the groups, ledgers and stock item fixtures. Result `ClosingReading = {asOf, groups, ledgers, stock, onAccount}` (decimals canonical strings, Tally sign kept, absent figure = `0.00`); a Tally error aborts the read, `last()` unchanged; no selection -> `Error('No company selected')`. `mapClosing({groups,ledgers,stock,asOf})` is the pure mapper. `applyClosing(storedMasters, reading, {force?})` (pure, no mutation) writes `closing_balance` (+ group `opening_balance` when Tally gave one), stock `closing_qty/closing_value/closing_rate` (rate = value/qty, 2 decimals half away from zero, as in masters) and `closing_as_of` onto stored `tm_group, tm_ledger, tm_stock_item` rows matched by `guid`, and returns `{tables, changed, unmatched, ops}`: `ops` = full-row `upsert` `ChangeOp`s in table order (groups, ledgers, stock items) only for rows whose figures changed (all matched rows with `force`); `unmatched` counts Tally rows with no stored master (the next master refresh brings them). `closingDue({lastRefreshedAt,now,syncChangedVouchers?,intervalH?})` -> boolean (default 24 h, constants `desktop.closing_balance_interval_h`; true after any sync that changed vouchers). Reports as Tally gives them, nothing recomputed: `gstSummaryInputs(ledgerRows)` -> `{heads:{<gst_duty_head>:{credit,debit,net,ledgers}}}` from the duty ledgers' closing balances grouped by the ledger's own `gst_duty_head` column (never by ledger name; Tally sign, Cr positive); `groupTotalsByNature(groupRows)` -> `{byNature}` sums root-group closing balances by `nature`; `onAccount` = per ledger the sum of bill allocations Tally marks `BILLTYPE = On Account` (tag and amount field `assumed`, TW-ONACCOUNT; the fixtures carry none).
